## 1. 目标

在现有 Android Emby 客户端中增加完整的在线图片库浏览和全屏查看能力：

- 从 `CollectionType=photos` 的媒体库进入图片目录。
- 浏览相册、文件夹和图片，支持分页和下拉刷新。
- 从任意图片开始全屏查看，并保持当前目录中的前后顺序。
- 1 倍状态左右滑动换图，放大后平移图片。
- 双击放大或复位，双指缩放，切图时重置缩放状态。
- 预取相邻图片，控制服务端图片尺寸和本地解码尺寸。
- 图片认证信息只进入请求头，不进入 URL、日志或磁盘缓存键。
- 保持加载、错误、空目录、会话过期和网络恢复行为可预测。

首版完成标准不是“能显示图片”，而是用户连续查看常规手机照片时，缓存命中和
相邻预取能够消除大部分可见等待，且不会因连续查看高分辨率图片导致明显内存增长
或崩溃。

## 2. 用户流程

### 2.1 图片库

1. 用户在“媒体库”页点击图片库。
2. 页面按目录层级展示 `PhotoAlbum`、`Folder` 和 `Photo`。
3. 相册和文件夹进入下一层；图片进入全屏查看器。
4. 列表滚动接近末尾时加载下一页，每页默认 60 项。
5. 下拉刷新清空当前分页状态并从第一页重新读取。

图片库必须按目录层级查询，首版不使用递归查询把所有图片平铺在一起。这样可以
保留服务器目录语义，也避免一次请求加载大型图库的全部元数据。

### 2.2 全屏查看

1. 查看器从用户点击的图片开始，而不是回到目录第一张。
2. 初始先显示网格中已经缓存的缩略图，再切换到适合屏幕的查看尺寸。
3. 1 倍状态左右滑动换图；缩放大于 1 倍时，横向拖动用于平移当前图片。
4. 双击在 1 倍和约 2.5 倍之间切换，缩放中心靠近双击位置。
5. 单击切换顶部和底部控制栏。
6. 控制栏显示返回、图片名称、当前位置和总数；总数未知时显示已加载位置。
7. 滑到已加载数据末端附近时，请求目录的下一页，并继续相邻图片预取。
8. 页面切换后释放上一页的手势状态，不长期持有每张图片的控制器。

首版采用“放大时锁定翻页”的明确规则。放大后必须缩回 1 倍再换图，不实现边缘
甩动换页，避免 `PageView` 与图片平移同时抢夺手势。

## 3. 首版范围

首版包含：

- 图片媒体库识别。
- 相册和文件夹分层浏览。
- 稳定尺寸的缩略图网格。
- 图片分页、去重、刷新和失败重试。
- 全屏沉浸式查看。
- 左右滑动、双指缩放、双击缩放、放大后平移。
- 当前图片前后各 2 张的有界预取。
- 缩略图到查看图的过渡。
- 服务端尺寸控制、本地解码尺寸控制和磁盘缓存。
- 请求头认证、Scope 化缓存键和脱敏日志。
- 自动化测试、真实服务器和 Android 设备验收。

首版非目标：

- 上传、删除、重命名、旋转或编辑服务器图片。
- 原图下载、系统分享和设置壁纸。
- EXIF 详情、地图、人物或时间轴聚合。
- GIF、Live Photo、RAW、全景图和动图专用播放器。
- 离线图片库。
- 跨服务器图库聚合。
- Android TV、键盘和遥控器专用交互。
- 自动幻灯片、随机播放和背景音乐。

幻灯片可作为第二阶段增量；它不能代替首版的预取和内存边界工作。

## 4. 当前基线与缺口

当前项目已经具备：

- `cached_network_image ^3.4.1`。
- `EmbyItem` 的类型、图片标签和主图宽高比。
- `EmbyApi.imageUrl` 的图片地址生成。
- 媒体库分页框架和通用图片占位组件。
- `ServerScope`、统一请求认证、诊断日志脱敏和会话过期处理。

当前缺口：

- `getLibraryItems` 只查询 `Movie,Series,Video`，图片库会显示为空。
- 媒体库中的所有条目都进入影视详情页，没有图片目录和查看器路由。
- `EmbyImage` 只有 URL、占位和淡入，不接收请求头、缓存键或解码尺寸。
- 图片 URL 当前包含 `api_key`，可能进入缓存元数据或错误文本。
- 没有图片分页状态所有者、相邻预取、全屏手势和生命周期管理。
- 没有图片库与大图查看相关测试。

## 5. Moonfin 参考结论

Moonfin-Core 当前图片查看器使用：

- `CachedNetworkImage` 磁盘缓存。
- 最大宽度 1920 的服务端图片请求。
- `InteractiveViewer` 进行 1 至 5 倍缩放。
- `AnimatedSwitcher` 进行 400 毫秒切换。
- 上一张、下一张和 5 秒幻灯片。

可以借鉴的行为：

- 图片查看是独立的全屏路由。
- 切图时复位缩放状态。
- 控制栏自动隐藏。
- 图片和相邻目录项由同一个查看会话持有。

不直接照搬的部分：

- Moonfin 查看器没有相邻图片预取。
- 没有手势左右翻页。
- 查看器没有显式限制本地解码尺寸。
- 一次最多读取 500 个兄弟图片，不适合作为大型图库分页方案。
- 首次切换未缓存图片时仍可能显示加载圈。

本项目只参考公开行为、职责划分和失败场景，所有代码与测试独立实现。

## 6. API 与数据模型

### 6.1 图片目录查询

在 `EmbyApi` 增加专用方法，不扩大现有影视查询的返回范围：

```dart
Future<List<EmbyItem>> getPhotoChildren({
  required String parentId,
  int startIndex = 0,
  int limit = 60,
})
```

请求约束：

```text
GET /Users/{userId}/Items
ParentId={parentId}
StartIndex={startIndex}
Limit={limit}
Recursive=false
IncludeItemTypes=Photo,PhotoAlbum,Folder
SortBy=SortName
SortOrder=Ascending
Fields=<现有 item fields>
EnableImages=true
```

真实服务器验收时记录不同 Emby 版本返回的容器类型。如果某些版本使用其他明确
类型表示图片目录，应在兼容层归一化，不能让 UI 猜测任意未知类型都是文件夹。

`EmbyItem` 增加只读语义：

```dart
bool get isPhoto => type == 'Photo';
bool get isPhotoContainer =>
    type == 'PhotoAlbum' || type == 'Folder';
bool get isPhotoLibrary =>
    collectionType?.toLowerCase() == 'photos';
```

首版不为图片复制一套服务器 Item 模型。只有当真实响应证明需要日期、宽高或方向
字段时，才向 `EmbyItem` 增加对应可空字段。

### 6.2 结构化图片请求

新增不可变的 `EmbyImageRequest`：

```dart
class EmbyImageRequest {
  final Uri uri;
  final Map<String, String> headers;
  final String cacheKey;
  final int decodeWidth;
  final int decodeHeight;
}
```

`EmbyApi` 增加图片请求构造方法：

```dart
EmbyImageRequest? imageRequest(
  EmbyItem item, {
  String type = 'Primary',
  int maxWidth = 600,
  int? maxHeight,
  int quality = 90,
})
```

约束：

- URI 只包含 `tag`、`maxWidth`、`maxHeight` 和 `quality`，不包含 `api_key`。
- `X-Emby-Token` 和授权信息只通过 HTTP 请求头发送。
- 图片下载只自动跟随同源重定向，跨源重定向必须在发送认证头前拒绝。
- 等待响应头和响应体连续无数据分别设置 15 秒超时，超时后中止底层 HTTP 请求，
  避免永久占用预取并发槽位。
- 缓存键包含 `ServerScope` 的 SHA-256 脱敏标识、Item ID、图片类型、Tag、
  宽高档位和质量。
- 缓存键和 `toString` 不得包含 Token、服务器 URL 或认证头。
- Tag 变化后自然产生新缓存键，不复用旧图片。

现有 `imageUrl` 在迁移期间保留，但图片组件和新查看器不得继续使用带 Token 的
URL。所有现有图片调用点迁移完成后再删除或限制该方法。

## 7. 图片尺寸与缓存策略

### 7.1 尺寸档位

避免为每个略有不同的布局宽度生成一份缓存，使用固定档位：

| 场景 | 服务端尺寸上限 | 本地解码上限 |
|---|---:|---:|
| 图片网格 | 宽高 384 或 512 档位 | 组件物理宽高 |
| 详情/预览 | 宽高 900 或 1200 档位 | 组件物理宽高 |
| 全屏查看 | 宽高最大 2560 | 两个维度都不超过 2560 |

全屏档位按 `屏幕最长逻辑边 * devicePixelRatio` 向上选择，最小 1280、最大 2560。
同一档位同时作为宽度和高度上限，避免超长竖图产生无界解码高度。首版不因 5 倍
缩放直接解码 5 倍屏幕尺寸；这会使 4K/8K 图片快速耗尽内存。

### 7.2 相邻预取

查看器在当前页稳定后预取：

```text
current - 2
current - 1
current + 1
current + 2
```

规则：

- 当前图优先，邻图最多两个并发请求。
- 翻页后重新计算窗口；已经缓存或正在请求的键不重复提交。
- 快速连续滑动使用代次编号忽略过期调度结果，不要求取消缓存库内部请求。
- 距已加载末尾 8 项以内时请求下一页元数据。
- 初始图片已经位于预取阈值内时立即续页，不依赖第一次翻页回调。
- 预取失败不记录为完成，后续窗口可再次调度；用户切到该图时仍显示局部重试状态。
- 会话退出、服务器切换或查看器销毁后停止新的预取调度。

### 7.3 渐进显示

进入查看器时复用网格缩略图作为低清预览：

1. 立即绘制已缓存缩略图。
2. 加载全屏尺寸图片。
3. 全屏图第一帧可用后进行 120 至 180 毫秒淡入。
4. 加载失败时保留缩略图并显示局部重试按钮。

不使用全屏加载圈覆盖已经可见的缩略图，也不通过 `AnimatedSwitcher` 长时间同时
保留两张完整解码图。

### 7.4 磁盘缓存边界

- 图片磁盘缓存最大 256 MiB，超过预算后按最近使用时间淘汰最旧条目。
- 同时保留最多 240 个对象，未使用条目的保留期为 14 天。
- 在线图片写入完成并空闲 2 秒后合并执行预算检查，避免每次下载同步扫描缓存。
- 账号菜单提供“清理图片缓存”，同时清空磁盘缓存、Flutter 内存缓存和 Live
  Image 缓存，并显示已清理大小。
- 缓存清理失败不能影响已经成功加载的图片。

## 8. 状态所有权

新增两个轻量控制器，不引入新的状态管理依赖。

### 8.1 `PhotoBrowserController`

负责：

- 当前目录 ID。
- 已加载条目、分页游标和 `hasMore`。
- 首次加载、追加加载、刷新和重试。
- 按 Item ID 去重。
- 丢弃刷新前启动、刷新后才返回的旧请求结果。

页面只订阅状态并发送 `loadMore`、`refresh` 和 `retry` 意图。

### 8.2 `PhotoViewerController`

负责：

- 当前目录、图片列表和当前索引。
- 从浏览页接收的初始分页上下文。
- 接近末尾时加载下一页并过滤目录容器。
- 相邻预取窗口和预取代次。
- 当前图片加载状态和可恢复错误。
- 控制栏显示状态及自动隐藏计时器。

每个可见图片页自己的 `TransformationController` 由页面持有。切页后销毁旧控制器，
避免控制器数量随图库长度增长。

`EmbyApi` 销毁后禁止再触发会话失效和远程能力回调。`AppController` 除校验
`ServerScope` 外，还校验回调来源是当前注册的同一个 API 实例，避免同一用户重新
登录后，旧会话的迟到 401/403 注销新会话。

## 9. 手势与页面状态机

状态：

```text
idle(scale=1)
  ├─ horizontal drag -> paging
  ├─ double tap -> zoomed
  └─ pinch -> zoomed

zoomed(scale>1)
  ├─ drag -> pan image
  ├─ pinch -> adjust scale
  └─ double tap -> idle(scale=1)

page changed
  └─ reset new page to idle(scale=1)
```

实现约束：

- 使用 `PageView.builder`，不预先创建全部图片页面。
- 当前页缩放大于 `1.01` 时，分页物理效果切换为不可滚动。
- 缩放范围首版为 1 至 5 倍。
- 双击目标约为 2.5 倍，并围绕点击位置计算变换。
- 切页和返回目录时不得把缩放矩阵写入全局状态。
- 单击控制栏手势不能吞掉缩放和平移手势。
- 图片页面具有固定布局边界；占位、错误和加载完成不能改变页面尺寸。

## 10. UI 方案

### 10.1 图片目录

- 复用现有页面背景、AppBar 和错误状态视觉语言。
- 网格使用稳定列宽和间距，不采用瀑布流，避免图片加载后重排。
- 相册/文件夹卡片显示文件夹图标、名称和可用封面。
- 图片卡片使用 `PrimaryImageAspectRatio` 选择裁切，但卡片外框保持固定比例。
- 加载更多使用底部进度；追加失败保留已有图片并提供局部重试。
- 空目录显示图片图标和“这个图片目录是空的”。

### 10.2 全屏查看器

- 黑色全屏背景，不放装饰性卡片。
- 图片以 `BoxFit.contain` 显示。
- 顶部控制栏：返回、名称、`当前位置 / 总数`。
- 底部首版不放冗余文字说明；只保留必要操作。
- 单击隐藏或显示控制栏，4 秒无操作自动隐藏。
- 进入时启用沉浸式系统 UI，退出时恢复应用默认 `edgeToEdge`。
- 不强制横竖屏，设备旋转后重新计算查看尺寸和解码边界。

## 15. 风险与处理

### Emby 目录类型差异

风险：不同服务器版本可能用不同类型表示图片目录。

处理：先保留 `PhotoAlbum` 和 `Folder` 的明确白名单，通过真实响应补兼容测试，不
对未知类型做宽泛推断。

### 缩放与翻页冲突

风险：`InteractiveViewer` 和 `PageView` 同时竞争横向拖动。

处理：首版在缩放大于 1 倍时锁定 PageView；用 Widget 测试和真机手势共同验收。

### 高分辨率图片内存

风险：连续解码原始 4K/8K 图片导致掉帧或 OOM。

处理：固定尺寸档位、服务端缩放、本地 `memCacheWidth`、有界页面创建和 Profile
内存门槛。首版不承诺像素级原图放大。

### Token 进入缓存

风险：带 `api_key` URL 被缓存管理器保存或进入异常文本。

处理：结构化图片请求、Header 认证、Scope 化缓存键和专门的安全回归测试。

### 大目录分页顺序变化

风险：浏览期间服务器内容变化导致重复或跳项。

处理：稳定排序、Item ID 去重、刷新重置；首版不实现游标快照或服务器事务视图。

## 17. 当前实现与验证记录

已实现：

- `EmbyImageRequest` 使用无 Token URI、认证头、SHA-256 Scope 缓存键和固定宽高档位。
- 图片缓存下载只跟随同源重定向，不向跨源地址发送 Emby 认证头。
- 图片缓存层返回 401/403 时只触发一次现有会话失效回调。
- 图片请求等待响应头和响应体停滞均有 15 秒超时，超时后中止底层请求。
- 已销毁 API 的迟到 401/403 不再触发会话失效，控制器按 Scope 和 API 实例双重校验。
- 图片磁盘缓存限制为 256 MiB、240 项和 14 天，超预算按 LRU 淘汰。
- 账号菜单可手工清理图片磁盘缓存和 Flutter 内存图片缓存。
- 现有首页、媒体库、详情和搜索图片全部迁移到结构化图片请求。
- 图片媒体库、相册/文件夹层级、60 项分页、刷新、去重和旧响应失效。
- 从首页和媒体库页按 `CollectionType=photos` 分流。
- 全屏 `PageView`、正确初始索引、位置显示、上一张/下一张和沉浸式系统 UI。
- 1 至 5 倍缩放、双击 2.5 倍、放大后锁定翻页和切页复位。
- 缩略图到查看图的渐进显示、失败局部重试和宽高最大 2560 的解码预算。
