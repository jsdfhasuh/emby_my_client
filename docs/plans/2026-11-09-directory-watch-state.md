# 目录浏览与观看状态改进计划

执行角色：ChatGPT Web。用户已授权在当前 `main` 分支实施、验证并推送，触发现有正式构建流程。

基线：`075c7660942cfa7d72cf06924188467d0b87f43f`。

## 目标与行为约定

以家庭视频和图片的目录浏览为主要入口。当前目录和子目录均提供媒体类型、观看状态筛选；筛选作用于当前目录的媒体，文件夹和相册入口始终保留，不递归打散目录结构。

视频卡片统一显示未观看、观看中、已观看。已观看以服务器 `Played` 为准；未被标为已观看但存在播放位置或百分比时显示观看中，已知时长显示进度。未看完筛选包含观看中，另提供观看中筛选。照片使用未查看、已查看的独立文案，并复用现有用户状态接口保存状态。

## 实施步骤

1. 扩展浏览状态：目录支持媒体类型与观看状态，仍禁止来源筛选和字母跳转；进入子目录继承目录筛选；图片保留已查看/未查看筛选，排除观看中。
2. 目录分页：保留既有非递归原始查询，在每一原始页应用统一筛选并保留容器。原始游标和总数继续用于分页，首个原始页无匹配时继续加载后页。界面在扫描完成前只显示已加载的匹配结果，完成后显示包含导航目录的准确结果数，不能把原始总数当作筛选后总数。
3. 统一目录、混合、照片卡片：加入有中文文字和无障碍语义的状态角标；视频观看中显示有效进度；保持完整图片前景、收藏标记和大字体布局。
4. 照片查看记录：只有前台当前页完整图片成功显示并持续约一秒才自动记为已查看。预取、错误页、快速划过、后台不记；保存失败不得显示成功；手动标为未查看后本次会话不自动标回。提供手动已查看/未查看入口。
5. 返回刷新：混合查看器记录本次实际播放/成功修改的项目 ID，等待视频停止后返回；列表主动重读这些项目的用户数据，处理筛选成员变化、数量和位置恢复。
6. 验证与交付：针对跨原始页、容器保留、状态语义、照片显示计时、失败回退、混合查看器退出与筛选后刷新进行测试；使用仓库固定 Flutter/Dart 工具链格式化、分析并运行相关测试。核对远端 main 无并发更新后提交推送，跟踪现有 Android/iPadOS 构建与发布。

## 验收重点

- 目录内可选择全部、未看完、观看中、已观看；纯照片筛选显示未查看、已查看。
- 进入子目录不丢失筛选；返回上级保留原浏览状态。
- 有筛选时文件夹/相册仍可进入，不能因其自己的 Played 值消失。
- 前 60 个原始条目均无匹配时，后续匹配条目仍能加载；分页偏移不使用筛选后的数量。
- 统计不冒充整个目录原始条目数；状态变化后不存在漏项、旧角标或错误数量。
- 看过的视频与未看过的视频在目录里有清晰区别，已观看重播时服务器 Played 优先。
- 图片的预加载或加载失败不写已查看；手动未查看不会马上被自动记录覆盖。
- 复用现有播放上报，不修改服务器的已播放阈值或原生播放引擎。
